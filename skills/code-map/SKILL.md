# Code map

## Workflow

1. Read `AGENTS.md` for project rules.
2. Classify the request and consult the matching row in `docs/code-map.md`; the map is canonical.
3. Read only the owning `.cpp`, its `include/claymore/*.hpp`, and directly related tests.
4. Make the smallest consistent change.
5. Run the narrowest relevant command: `make test` for core, `make verify-docs` for guidance/map changes, and the relevant `make verify-*` target for GUI or install changes.
6. Update the map only when ownership, entry points, commands, or generated-data rules change.

## Quick ownership

- CLI → `src/main.cpp`; GUI lifecycle → `gui/main_gui.cpp`.
- Protocol/effects → `src/protocol.cpp`, `src/effects.cpp` and matching headers.
- Device/layout/design/settings/sync → `src/device.cpp`, `src/layout.cpp`, `src/design.cpp`, `src/settings.cpp`, `src/sync_server.cpp`.
- GTK state/panels → `gui/app.*`, `gui/panels.cpp`; tray/icon/canvas → `gui/tray.cpp`, `gui/icon.cpp`, `gui/keyboard_view.*`.
- Tests → `tests/test_core.cpp`; generators/package/verification → `tools/`.

## Must not forget

- Effect apply: grant → effect → optional Quicksand colours → select slot → `0x50 0x55` commit → release.
- Coloured Wave needs pattern bit 5; colourless Wave must not.
- Firmware speed 0 is fastest; use `speed_to_percent()`.
- `paint` is a live direct-mode session and does not revoke; release or apply an effect to hand control back.
- Painted designs are text files and must be reapplied; the Claymore cannot save arbitrary per-key designs.
- `src/layout_data.cpp` is generated by `tools/gen_layout.py`.

## Token discipline

- Do not paste full source files into notes or responses.
- Search symbols first, then read bounded windows.
- Prefer this map over README for implementation navigation.
- Do not inspect generated/build output unless diagnosing an artifact.
- Report changed files, behavior, tests, and risks only.

## Tool compatibility

This skill uses ordinary Markdown and standard YAML front matter. Cline is activated by `.clinerules/code-map.md`; other agents should read `AGENTS.md` and `docs/code-map.md`, or copy/symlink those files to their preferred rules location.
