# Code map

## Purpose

Navigate this C++17 project without loading the whole repository. Read `AGENTS.md` first; use `docs/code-map.md` as the canonical compact map. Keep searches constrained to the owning module and its public header.

## Workflow

1. Classify the request: protocol, effect, device, layout, design, settings, sync, CLI, GUI, or packaging.
2. Read the matching row in `docs/code-map.md`.
3. Read only the listed `.cpp`, its `include/claymore/*.hpp`, and directly related tests.
4. Make the smallest consistent change.
5. Run `make test` for core changes; add `make verify-gui` / `make verify-design` for GUI changes and `make verify-install` for install changes.
6. Update the map only when ownership, entry points, or workflows change.

## Minimal map

- `src/main.cpp` — CLI parsing and command composition.
- `src/protocol.cpp` + `include/claymore/protocol.hpp` — HID packet builders and constants.
- `src/effects.cpp` + `include/claymore/effects.hpp` — presets, speeds, apply sequence.
- `src/device.cpp`, `src/hidraw.cpp` — detection, sessions, direct-mode I/O.
- `src/layout.cpp`, generated `src/layout_data.cpp` — variants, frame geometry, hit testing.
- `src/design.cpp`, `src/settings.cpp` — text designs and key/value config.
- `src/sync_server.cpp` — RGBC UNIX-datagram sync protocol.
- `gui/main_gui.cpp` — GTK lifecycle, arguments, update loop.
- `gui/app.*`, `gui/panels.cpp` — GUI state, panels, callbacks.
- `gui/tray.cpp`, `gui/icon.cpp`, `gui/keyboard_view.*` — tray, emblem, canvas.
- `tests/test_core.cpp` — hardware-free regression suite.
- `tools/` — layout generator, package builder, verification scripts.

## Commands

```sh
make                 # build, GUI if available, tests
make cli             # CLI only
make gui             # GUI only
make test            # core tests
make verify-gui      # GUI pixel check; display required
make verify-design   # design-tab interaction check; display required
make verify-install  # staged installation check
make package         # .deb
```

## Non-negotiable protocol notes

- Keep `effect_reports()` order: grant, effect, optional Quicksand colors, select slot, `0x50 0x55` commit, release. The commit is mandatory.
- Coloured Wave requires bit 5 (`0x20`); colourless Wave must leave it clear.
- Firmware speed `0` is fastest; use `speed_to_percent()`.
- Direct mode is a live session. `paint` does not revoke; use release or an effects apply to hand control back.
- Painted designs are text files and must be reapplied; Claymore cannot save arbitrary per-key designs.
- `src/layout_data.cpp` is generated by `tools/gen_layout.py`.

## Token discipline

- Do not paste full source files into notes or responses.
- Search symbols, then read a bounded window.
- Prefer the map over README for implementation navigation.
- Do not inspect generated/build output unless diagnosing a build artifact.
- Keep response summaries to changed behavior, tests, and unresolved risks.
