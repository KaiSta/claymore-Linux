# AGENTS.md

Linux C++17 control app for an ASUS ROG Claymore. Core uses only libc; GTK 3 is optional for the GUI.

## Read order

1. Read this file for rules and workflow.
2. Consult `docs/code-map.md` when locating code or assessing cross-module impact.
3. Read only the owning implementation, its public header, and directly related tests.
4. Run the narrowest relevant check.

## Commands

- `make` — build all available targets and run tests.
- `make cli` / `make gui` — build one binary.
- `make test` / `make check` — hardware-free core tests.
- `make verify-docs` — validate agent documentation and map freshness.
- `make verify-gui` / `make verify-design` — display-dependent GUI checks; may require X11 and AT-SPI tooling.
- `make verify-install` — staged install/package check.
- `make package` — build the `.deb`.
- `make clean` — remove generated `build/` and `bin/` output.
- `PREFIX=$HOME/.local make install` — user-local install; `DESTDIR` stages files.

## Architecture

- `src/`, `include/claymore/` — reusable core; `src/main.cpp` is CLI composition.
- `gui/` — GTK 3 application, state, widgets, tray, and Cairo icon.
- `tests/test_core.cpp` — hardware-free regression suite.
- `tools/` — layout generator, packaging, and verification scripts.
- `contrib/`, `udev/`, `assets/`, `docs/` — install data and documentation.
- Core discovers `/sys` and writes `/dev/hidraw*`; it does not depend on hidapi/libusb/libudev.
- Do not commit generated `build/` or `bin/` output; `.gitignore` owns it. Keep only deliberate source assets under version control.
- User data is under `~/.config/claymore`; `XDG_CONFIG_HOME` and `CLAYMORE_CONFIG_DIR` are supported.

## Hard rules

- Preserve the firmware-effect sequence in `src/effects.cpp`: grant, effect/Quicksand colours, select slot, **commit `0x50 0x55`**, release. The commit is mandatory; omission makes the effect flash temporarily and revert.
- Preserve `protocol::effect()`'s bit-5 pattern rule for coloured Wave; colourless Wave keeps bit 5 clear. Keep packet tests synchronized.
- Firmware speed `0` is fastest. Use `speed_to_percent()` for the user-facing scale and existing per-effect defaults.
- Direct mode is a live host session. `paint` retains the final frame and does not revoke; use `claymore release`, GUI hand-back, or an Effects apply to return control.
- Direct mode is a live host session. `paint` retains the final frame and does not revoke; daemon/ordinary direct-mode callers opt into best-effort destructor release, while the GUI design mode deliberately does not.
- Sparse sync slots are uint8 on the wire (0..255); `sync_encode()` rejects larger slots instead of truncating them.
- `src/layout_data.cpp` is generated by `tools/gen_layout.py`; do not hand-edit it. Use the exact command documented in `README.md` and `docs/code-map.md`.
- Preserve OpenRGB/Mola19 attribution and GPL-2.0-or-later notices for protocol/layout data.

## Conventions

- Match existing C++17 style, naming, include order, and small pure helpers. Avoid new dependencies without a strong reason.
- Keep packet bytes and wire formats in `src/protocol.cpp` / `src/sync_server.cpp`.
- Keep shared parsers in core; never duplicate design/settings parsing in GUI or CLI.
- User-config writes are atomic: use the existing write helpers and test failure paths rather than writing directly to the final file.
- Add or update `tests/test_core.cpp` for core behavior. Run `make verify-*` for affected GUI/install behavior.
- Keep CLI, man pages, README, desktop metadata, and service files aligned with user-visible changes.
- Do not commit, push, reset, or overwrite unrelated work unless explicitly asked.
